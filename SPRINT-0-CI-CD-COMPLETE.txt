TROUBLESHOOTING QUICK REFERENCE
================================================================================

Coverage Below 90%:
  Solution: Write more unit tests, focus on untested code paths
  Local test: poetry run pytest src/tests/ --cov=src

Linting Failures:
  Solution: Fix code style issues
  Local test: poetry run ruff check src/

Type Check Failures:
  Solution: Add type annotations to functions
  Local test: poetry run mypy --strict src/

Security Vulnerabilities:
  Solution: Fix code issues or update dependencies
  Local test: poetry run bandit -r src/

Build Failures:
  Solution: Check pyproject.toml syntax and dependencies
  Fix: Ensure all dependencies are declared in poetry config

Flaky Tests:
  Solution: Identify test dependencies, use retries, clean state
  Test: poetry run pytest -x -v (stop on first failure)

For detailed solutions, see Troubleshooting Guide in:
  STORY-0-AUTOMATION-REPORT-2026-02-28.md

Subject: Sprint 0 CI/CD Pipeline is Live

Hi team,

The GitHub Actions CI/CD pipeline is now active. Here's what changed:

When you create a PR:
  - GitHub Actions automatically runs tests (Python 3.11, 3.12, 3.13)
  - Code coverage must be >=90%
  - All linting/type checks must pass
  - Security scans must find no critical issues
  - 2 approvals required (main) or 1 (develop)
  - Merge is blocked until all checks pass

Before pushing code:
  poetry run pytest src/tests/ --cov=src  # Check coverage
  poetry run ruff check src/               # Check linting
  poetry run mypy --strict src/            # Check types
  poetry run bandit -r src/                # Check security

If checks fail:
  - See STORY-0-AUTOMATION-REPORT-2026-02-28.md (Troubleshooting)
  - Or ask in #engineering for help
