## Правила Использования Терминов

### 1. Первое Упоминание
**При первом упоминании термина в диалоге:**

```markdown
**Speed Multiplier (Множитель Скорости)** - во сколько раз быстрее можно сделать проект по сравнению с "традиционным" ручным кодированием.

💡 Простыми словами: Представь, что обычно ты пишешь код руками 12 недель. Но если Claude Code (LLM) пишет за тебя 90% кода, ты финишируешь за 1 неделю. Это Speed Multiplier 12x (12 раз быстрее).
```

**Формат:**
```
**Термин (Русский Перевод)** - краткое определение на русском.

💡 Простыми словами: Объяснение для 16-летнего с примером.
```

## Мастер-Глоссарий Life OS v3

### Категория: Foundation Steps (Фундаментальные Шаги)

#### Точка А (Project Stage / Current State)
**Определение:** Текущее состояние проекта - что уже готово, что работает, что требует завершения.

**Физический смысл:** Ты не можешь спланировать путь, если не знаешь, где ты сейчас находишься. "Точка А" = твоё текущее местоположение на карте проекта.

**Пример для 16-летнего:**
> Представь, что ты делаешь игру. "Точка А" - это ответ на вопрос: "Что у меня уже есть?"
> - Если у тебя только идея → Точка А = 0%
> - Если у тебя уже есть работающий персонаж + 3 уровня → Точка А = 40%
> - Если игра уже запущена и есть 100 игроков → Точка А = 70%
>
> Зная Точку А (40%), ты понимаешь: "Осталось сделать 60%, а не 100%!"

**Аналогия:**
- Точка А = "Где я сейчас?" на GPS
- Точка Б = "Куда я иду?"
- Путь = "Что нужно сделать, чтобы дойти?"

**Связанные термины:** Completion Percentage, Timeline Adjustment

---

#### Speed Multiplier (Множитель Скорости)
**Определение:** Во сколько раз быстрее можно завершить проект по сравнению с традиционной ручной разработкой (baseline = 1x).

**Физический смысл:** Если традиционно разработчик пишет код руками за 12 недель, а с LLM (Claude Code) за 1 неделю → Speed Multiplier = 12x.

**Пример для 16-летнего:**
> Представь, что ты пишешь сочинение. Обычно на 10 страниц уходит 5 часов.
>
> **Традиционный способ (1x):**
> - Ты сам пишешь каждое слово → 5 часов
>
> **С LLM помощником (10x):**
> - Ты говоришь ChatGPT: "Напиши сочинение про экологию"
> - ChatGPT пишет 80% за 10 минут
> - Ты редактируешь 20 минут
> - Итого: 30 минут вместо 5 часов → **10x faster**
>
> Speed Multiplier = 10x

**Формула:**
```
Speed Multiplier = Traditional Time ÷ Actual Time

Пример:
- Traditional: 12 weeks
- With LLM: 1 week
- Speed Multiplier = 12 ÷ 1 = 12x
```

**Факторы влияния:**
- **LLM-assisted (10x-50x):** Claude Code пишет 80-90% кода
- **No-code tools (5x-20x):** Supabase, Bubble вместо ручного кодирования
- **Existing codebase (+2x-5x):** Переиспользование готового кода
- **Hybrid (20x-100x):** Комбинация всех подходов

**Связанные термины:** LLM, No-code, Traditional Development

#### LLM (Large Language Model / Большая Языковая Модель)
**Определение:** Искусственный интеллект (AI), который понимает и генерирует текст, код и рассуждения.

**Физический смысл:** Очень умный помощник, который может писать код, объяснять концепции, решать задачи на основе обучения на миллиардах примеров.

**Пример для 16-летнего:**
> Представь супер-умного робота-помощника, который:
> - Прочитал всю документацию по Python, JavaScript, React
> - Видел миллионы примеров кода
> - Может написать программу по твоему описанию
>
> Ты говоришь: "Сделай калькулятор на React с кнопками"
> LLM пишет весь код за 2 минуты.
>
> **Примеры LLM:**
> - ChatGPT (OpenAI)
> - Claude (Anthropic) ← используется в Life OS
> - GitHub Copilot (для кода)

**Применение в Life OS:**
- Claude Code пишет 80-90% кода
- Ты проверяешь, редактируешь, интегрируешь
- Результат: 10x-50x faster разработка

**Связанные термины:** Speed Multiplier, Claude Code, AI-Assisted Development

---

#### Completion Percentage (Процент Готовности)
**Определение:** Сколько процентов проекта уже сделано по 4 измерениям: Technical (техника), Product (продукт), Market (рынок), Operations (операции).

**Физический смысл:** Как в игре "прохождение": 0% = только начал, 50% = полпути, 100% = проект завершён.

**Пример для 16-летнего:**
> Делаешь игру для школьного проекта:
>
> **Technical (техника): 40%**
> - ✅ Персонаж двигается
> - ✅ 3 уровня работают
> - ❌ Нет сохранений
> - ❌ Нет звука
>
> **Product (продукт): 30%**
> - ✅ Основная механика готова
> - ❌ Нет главного меню
> - ❌ Баланс не настроен
>
> **Market (рынок): 10%**
> - ❌ Никто не тестировал
> - ❌ Нет обратной связи
>
> **Operations (операции): 20%**
> - ✅ Ты один работаешь
> - ❌ Нет документации
>
> **Общий Completion: 25%** (средневзвешенный)
>
> Значит, осталось сделать 75%!

**Формула:**
```
Overall Completion =
  Technical (30% вес) +
  Product (30% вес) +
  Market (25% вес) +
  Operations (15% вес)
```

**Связанные термины:** Точка А, Timeline Adjustment

#### Timeline Adjustment (Корректировка Сроков)
**Определение:** Пересчёт реалистичных сроков с учётом того, что уже готово (Completion %) и какие ресурсы доступны (Speed Multiplier).

**Физический смысл:** Если проект 50% готов, нужно завершить только 50% (а не 100%). Если Speed Multiplier 10x, то делаем в 10 раз быстрее.

**Пример для 16-летнего:**
> Планировал сделать игру за 12 недель (с нуля).
>
> **Проверка Точки А:**
> - Уже готово: 50% (персонаж + 3 уровня)
> - Осталось: 50%
>
> **Проверка Speed Multiplier:**
> - Традиционно: пишу код руками (1x)
> - С Unity Asset Store + LLM подсказками: 5x faster
>
> **Timeline Adjustment:**
> ```
> Realistic Timeline = Traditional × (100 - Completion%) ÷ Speed Multiplier
>                    = 12 weeks × 50% ÷ 5x
>                    = 6 weeks ÷ 5
>                    = 1.2 weeks ≈ 1-2 недели
> ```
>
> Вместо 12 недель → **1-2 недели**! (10x разница)

**Формула:**
```
Adjusted Timeline = Traditional Estimate × (100 - Completion%) / 100 ÷ Speed Multiplier

Пример:
- Traditional: 12 weeks (если делать с нуля вручную)
- Completion: 50% (уже готово)
- Speed Multiplier: 10x (LLM помогает)
- Adjusted = 12 × 0.5 ÷ 10 = 0.6 weeks = 3-4 дня
```

**Связанные термины:** Точка А, Speed Multiplier, Completion Percentage

### Категория: Tech Stack (Технологический Стек)

#### Traditional Stack (Традиционный Стек)
**Определение:** Классический набор технологий для разработки: ручное написание кода, настройка серверов, базы данных вручную.

**Физический смысл:** "Старый" способ делать проекты - всё с нуля, вручную, без современных инструментов.

**Пример для 16-летнего:**
> Делаешь приложение для заказа пиццы.
>
> **Traditional (старый способ):**
> 1. Пишешь backend на Node.js вручную (3 недели)
> 2. Настраиваешь PostgreSQL базу данных (1 неделя)
> 3. Пишешь frontend на React с нуля (4 недели)
> 4. Настраиваешь сервер на AWS (2 недели)
> 5. Настраиваешь авторизацию (2 недели)
> 6. **Итого: 12 недель**
>
> Это как построить дом с нуля: копать фундамент, класть кирпичи по одному...

**Примеры:**
- Backend: Node.js + Express (написан вручную)
- Database: PostgreSQL (настройка вручную)
- Frontend: React (компоненты с нуля)
- Hosting: AWS EC2 (ручная настройка)

**Связанные термины:** Modern Stack, Optimal Stack

---

#### Modern Stack (Современный Стек)
**Определение:** Более быстрый набор технологий: фреймворки, библиотеки, managed services.

**Физический смысл:** "Средний" способ - используешь готовые решения, но всё ещё много ручной работы.

**Пример для 16-летнего:**
> Делаешь приложение для заказа пиццы.
>
> **Modern (современный способ):**
> 1. Используешь Next.js фреймворк (встроенный backend) (1 неделя)
> 2. Используешь Prisma ORM для базы (3 дня)
> 3. Используешь Tailwind CSS для дизайна (2 дня)
> 4. Деплой на Vercel одной кнопкой (1 час)
> 5. NextAuth.js для авторизации (2 дня)
> 6. **Итого: 2-3 недели**
>
> Это как построить дом из готовых модулей: стены уже есть, просто собираешь!

**Примеры:**
- Backend: Next.js API routes (встроенный)
- Database: Prisma + PostgreSQL (managed)
- Frontend: Next.js + Tailwind CSS
- Hosting: Vercel (auto-deploy)
- Auth: NextAuth.js (готовая библиотека)

**Speed:** 4x-5x faster чем Traditional

**Связанные термины:** Traditional Stack, Optimal Stack

---

#### Optimal Stack (Оптимальный Стек)
**Определение:** Самый быстрый набор технологий: LLM генерирует код, no-code для UI, managed services для backend.

**Физический смысл:** "Лучший" способ - максимальная скорость, минимум ручной работы.

**Пример для 16-летнего:**
> Делаешь приложение для заказа пиццы.
>
> **Optimal (оптимальный способ):**
> 1. Claude Code пишет 90% кода за тебя (1 день)
> 2. Supabase = instant backend + база + auth (2 часа setup)
> 3. v0.dev генерирует UI компоненты (2 часа)
> 4. Vercel auto-deploy (10 минут)
> 5. Stripe для оплаты (готовая интеграция) (1 час)
> 6. **Итого: 3-5 дней**
>
> Это как переехать в готовый дом: всё уже есть, просто въезжаешь!

**Примеры:**
- Backend: Supabase (instant API + DB + Auth)
- Frontend: v0.dev (UI generation) + Claude Code (logic)
- Hosting: Vercel (one-click)
- Payments: Stripe (pre-built)
- Code generation: Claude Code / Cursor AI

**Speed:** 20x-50x faster чем Traditional

**Связанные термины:** Traditional Stack, Modern Stack, No-Code

---

#### No-Code (Безкодовые Инструменты)
**Определение:** Инструменты, которые позволяют создавать приложения без написания кода - через визуальный интерфейс (drag-and-drop).

**Физический смысл:** "Конструктор" для приложений - как Lego, только для сайтов и приложений.

**Пример для 16-летнего:**
> Хочешь сделать сайт для своего блога.
>
> **С кодом (Traditional):**
> - Учишь HTML, CSS, JavaScript (3 месяца)
> - Пишешь код (2 недели)
>
> **No-Code (Webflow/Wix):**
> - Открываешь Webflow
> - Перетаскиваешь блоки мышкой (drag-and-drop)
> - Выбираешь шаблон
> - Меняешь текст и картинки
> - **Готово за 2-3 часа**
>
> Это как в Minecraft: не пишешь код блоков, просто ставишь их!

**Примеры инструментов:**
- **Websites:** Webflow, Wix, Squarespace
- **Apps:** Bubble.io, Glide, Adalo
- **Backend:** Supabase, Firebase
- **Automation:** Zapier, Make (formerly Integromat)
- **Databases:** Airtable, Notion

**Плюсы:**
- ✅ Очень быстро (5x-20x faster)
- ✅ Не нужно уметь кодить
- ✅ Визуальный интерфейс

**Минусы:**
- ❌ Ограниченная кастомизация
- ❌ Зависимость от платформы
- ❌ Сложности при масштабировании

**Связанные термины:** Low-Code, Speed Multiplier, Optimal Stack

### Категория: Frameworks & Methods (Фреймворки и Методологии)

#### MCDA (Multi-Criteria Decision Analysis / Многокритериальный Анализ Решений)
**Определение:** Метод оценки идей/проектов по нескольким критериям (например: сложность, потенциал, стратегическое соответствие) с весами.

**Физический смысл:** Объективная оценка проекта через несколько "линз" с разными приоритетами.

**Пример для 16-летнего:**
> Выбираешь, какую игру делать для школьного проекта.
>
> **Вариант А:** Шутер (сложная 3D графика)
> **Вариант Б:** Платформер (простая 2D графика)
>
> **MCDA оценка:**
>
> | Критерий | Вес | Шутер | Платформер |
> |----------|-----|-------|------------|
> | Сложность (простота = лучше) | 40% | 3/10 (сложно) | 8/10 (легко) |
> | Интересность | 30% | 9/10 (круто) | 6/10 (норм) |
> | Срок сдачи (успею?) | 30% | 2/10 (нет) | 9/10 (да) |
>
> **Шутер:** (3×0.4) + (9×0.3) + (2×0.3) = 1.2 + 2.7 + 0.6 = **4.5/10**
> **Платформер:** (8×0.4) + (6×0.3) + (9×0.3) = 3.2 + 1.8 + 2.7 = **7.7/10**
>
> **Вывод:** Делай платформер! (объективно лучше по всем критериям)

**Критерии в Life OS:**
1. **Complexity (Сложность):** 20% вес
2. **Impact (Потенциал):** 25% вес
3. **Alignment (Стратегическое соответствие):** 30% вес
4. **Resource Efficiency (Эффективность ресурсов):** 25% вес

**Формула:**
```
Total Score = (Criterion1 × Weight1) + (Criterion2 × Weight2) + ...

Threshold (порог): ≥6.5/10 → PROCEED
                   <6.5/10 → DEFER or KILL
```

**Связанные термины:** Scoring, Strategic Alignment

#### Six Thinking Hats (Шесть Шляп Мышления)
**Определение:** Метод анализа проблемы с 6 разных точек зрения (факты, эмоции, критика, оптимизм, креатив, процесс).

**Физический смысл:** Посмотреть на идею глазами 6 разных людей - эксперта, оптимиста, пессимиста, креативщика и т.д.

**Пример для 16-летнего:**
> Идея: Запустить YouTube канал о программировании.
>
> **Белая шляпа (Факты):**
> - Сейчас 50K подписчиков на канале "Fireship"
> - Средний просмотр tech видео: 100K
> - Монетизация: $2-5 за 1000 просмотров
>
> **Красная шляпа (Эмоции):**
> - Мне нравится программировать!
> - Страшно говорить на камеру
> - Волнение от идеи делиться знаниями
>
> **Чёрная шляпа (Критика):**
> - ❌ Уже много tech каналов (конкуренция)
> - ❌ Нужно много времени (монтаж 4-6 часов на видео)
> - ❌ Первые 6 месяцев = 0 денег
>
> **Жёлтая шляпа (Оптимизм):**
> - ✅ Unique angle: программирование для школьников
> - ✅ Растущий рынок (все учат код)
> - ✅ Может вырасти до 100K+ подписчиков
>
> **Зелёная шляпа (Креатив):**
> - Формат: "Игра за 10 минут" (quick tutorials)
> - Стиль: Meme-driven (юмор + обучение)
> - Сотрудничество с другими YouTube каналами
>
> **Синяя шляпа (Процесс):**
> - Week 1-2: Записать 5 видео
> - Week 3-4: Запустить канал
> - Week 5-12: 2 видео в неделю (consistency)
> - After 12 weeks: Оценить результаты
>
> **Вывод:** После анализа видно все плюсы, минусы и план действий!

**6 шляп:**
1. **Белая** (факты): Что мы знаем?
2. **Красная** (эмоции): Что чувствуем?
3. **Чёрная** (критика): Что может пойти не так?
4. **Жёлтая** (оптимизм): Что хорошего?
5. **Зелёная** (креатив): Какие новые идеи?
6. **Синяя** (процесс): Какой план?

**Связанные термины:** Consilium, MCDA

### Категория: AI Tools (AI Инструменты)

#### Claude Code (Клод Код)
**Определение:** AI coding assistant, который пишет код на основе твоих инструкций.

**Физический смысл:** Супер-умный программист-робот, который понимает, что ты хочешь, и пишет код за тебя.

**Пример для 16-летнего:**
> Хочешь сделать калькулятор на Python.
>
> **Без Claude Code:**
> - Открываешь учебник Python
> - Изучаешь синтаксис (2 часа)
> - Пишешь код (1 час)
> - Исправляешь баги (1 час)
> - **Итого: 4 часа**
>
> **С Claude Code:**
> - Говоришь: "Напиши калькулятор на Python с +, -, ×, ÷"
> - Claude генерирует код за 10 секунд
> - Ты проверяешь, тестируешь (10 минут)
> - **Итого: 10 минут** (24x faster!)

**Что умеет:**
- Писать код на любом языке (Python, JavaScript, C++, etc.)
- Объяснять код
- Находить и исправлять баги
- Генерировать тесты
- Рефакторинг (улучшение) кода

**Где используется:**
- VS Code (расширение)
- Cursor AI (редактор кода)
- Cline (интеграция)

**Связанные термины:** LLM, Speed Multiplier, AI-Assisted Development

#### Supabase (Супабейс)
**Определение:** Backend-as-a-Service (BaaS) - готовый backend (сервер + база данных + авторизация) за 5 минут.

**Физический смысл:** "Готовый сервер в коробке" - не нужно настраивать backend вручную, всё уже работает.

**Пример для 16-летнего:**
> Делаешь приложение для списка задач (to-do list).
>
> **Без Supabase (Traditional):**
> 1. Устанавливаешь Node.js (1 час)
> 2. Устанавливаешь PostgreSQL базу (2 часа)
> 3. Пишешь API endpoints (создать задачу, удалить, обновить) (3 дня)
> 4. Настраиваешь авторизацию (регистрация, логин) (2 дня)
> 5. Настраиваешь сервер (hosting) (1 день)
> 6. **Итого: 6-7 дней**
>
> **С Supabase:**
> 1. Создаёшь проект в Supabase (5 минут)
> 2. Создаёшь таблицу "tasks" (2 минуты)
> 3. Supabase автоматически генерирует API (0 минут)
