## File Structure Quick Reference

### What's in Each Workflow Directory

```
workflow-dir/
├── workflow.md or workflow.yaml    ← START HERE
├── instructions.md                 ← Detailed guidance
├── checklist.md                    ← Track progress
├── steps/                          ← Individual steps
│   └── step-*.md
├── steps-c/                        ← Creation steps
├── steps-e/                        ← Editing steps
├── steps-v/                        ← Validation steps
├── steps-b/                        ← Brainstorm steps
├── templates/                      ← Templates to use
│   └── *.template.md
└── data/                           ← Reference info
    └── *.md
```

### Standard Support Files

Every workflow typically has:
1. **workflow.md/yaml** - Definition (MANDATORY)
2. **instructions.md** - How-to guide
3. **checklist.md** - Progress tracker
4. **steps/** - Actionable steps
5. **templates/** - Reusable artifacts
6. **data/** - Reference materials

## Coordinator Commands

### Load Workflow
```
1. Read: <path>/workflow.md or workflow.yaml
2. Extract: title, description, phases
3. Get steps from: steps/, steps-c/, steps-e/, steps-v/, steps-b/
4. Read: instructions.md (if exists)
5. Get progress tracker: checklist.md
```

### Execute Workflow
```
1. For each step in order:
   - Read step-*.md file
   - Follow instructions
   - Execute action
   - Mark checklist item
2. Apply templates from templates/ as needed
3. Reference data from data/ for context
```

### Spawn Agents
```
1. Identify multi-step workflow
2. Create concurrent tasks for independent steps
3. Use hierarchical topology (CLAUDE.md guidance)
4. Assign specialized agents to each step type
5. Coordinate via shared memory
```
